# ByteKibble iOS 产品、设计与上架实施策划

版本：策划 v1.0 · 2026-09-13

品牌：MU Labs · 产品中文名：字节猫粮

依据：当前 macOS 仓库 `94c570e`、build 50 的实现边界、用户已选定的品牌方向，以及文末 Apple 官方资料。

> 本文是待实施的产品与工程方案，不是功能上线公告。此次只编制策划，不修改现有 App、不创建云端资源、不提交审核。所有尺寸、性能预算和排期均为项目建议，不冒充 Apple 规定或已有测试结果。目标是具备正常 App Store 提交和维护条件；最终审核、地区资格和账号能力需要分别核验，不能保证过审。

阅读路线：第 1–4 节看产品范围与页面；第 5–6、13–14 节看设计和交互；第 7–12、15 节看数据、同步与实现；第 16–20 节看验收、上架和排期。全部方案中的“首发”“支持”均指规划目标，非当前 build 50 已提供。

## 1. 产品结论与首发定义

**做一款原生、隐私优先的订阅流量管理 App：添加一次订阅，在手机、小组件和 Mac 上清楚知道还剩多少、数据有多新、什么时候需要处理。**

建议首发支持 iOS 26+，以原生 Liquid Glass 为设计基线；同一 iOS 产品包含 iPadOS 26+ 自适应界面。不会为旧 iOS 复制一套假玻璃，也不会要求用户安装测试版系统。构建时使用 Apple 当时接受的正式 Xcode/SDK；SDK 提交要求与最低运行系统是两回事。[Apple 当前提交要求](https://developer.apple.com/news/upcoming-requirements/)

### 1.1 产品承诺

- 查看服务商返回的套餐流量、到期信息；多个订阅独立工作。
- 无需注册 MU Labs 账号；默认本机保存，云同步由用户主动启用。
- 同步订阅与管理设置，不将一台设备的旧流量读数伪装为另一台设备的实时结果。
- 通过小组件和提醒减少反复打开代理客户端的操作。
- 不知道的内容明确写未知；失败、过期、用完、未同步是不同状态。

### 1.2 明确不做

- 不提供 VPN、代理节点、连接开关、测速、解锁、节点购买或服务商推荐市场。
- 不扫描 iPhone 中其他 App 的私有文件，不读取 Quantumult X / Surge / Stash 的内部数据库。
- 不执行订阅中的脚本、规则、模块或节点配置；不经过在线订阅转换服务。
- 不承诺后台常驻、秒级流量、准时跨设备同步或所有 VPN 账号兼容。
- 首发不做 Android、Apple Watch、社交排行榜、AI 分析、账户体系或第三方广告。

### 1.3 什么才算完整首发

P0 是首发必做，不是可以随便删减的 MVP：原生主界面、多订阅管理、导入与校验、真实流量查询、缺失字段处理、手动重置、日期与低流量提醒、iCloud 可选同步、桌面/锁屏小组件、隐私与数据管理、五种语言、iPad 适配、可供审核的演示与测试材料。

P1 是完整产品后续增强：附近设备传输、口令加密备份、更多历史工具与可选收费能力。它们有设计方案，但不应以占位按钮进入首发。若要首发包含附近传输，必须追加对应安全与设备验收，不能把它当成廉价附属按钮。

## 2. 现有基础与必须新建的部分

| 领域 | 当前仓库已具备 | iOS 工作 |
| --- | --- | --- |
| 订阅导入 | HTTPS 与部分客户端导入包装解析 | 抽成平台无关模块，增加分享扩展、扫码、重复识别 UI |
| 流量解析 | `Subscription-Userinfo`、SIP008 合计字段 | 复用规则和样例，扩充缺失/异常语义模型 |
| 网络安全 | TLS、同主机同端口 HTTPS 重定向、2 MiB 正文限制、取消 | 移除 Mac 本机代理端口尝试，适配 iOS 调度与限流 |
| 保存 | Mac 本机钥匙串、旧偏好迁移 | iOS 数据保护、访问组、显式同步、跨账号隔离 |
| 视觉 | 中性灰卡片、金色粮袋品牌、圆润数字、五语言资源 | 原生 iPhone/iPad 页面与系统交互，不搬菜单栏布局 |
| 应用更新 | macOS Sparkle / GitHub OTA | iOS 完全不包含 Sparkle，走 App Store / TestFlight |
| 自动发现 | 特定 Mac 客户端本地配置 | 保留在 Mac；移动端只接收用户选择同步/导入的订阅 |
| 提醒/历史/同步 | 不应从现有菜单栏能力推断已完成 | 新建业务模型、状态机、持久化和验收 |

工程事实：`Package.swift` 当前只有 macOS 13 可执行目标；`Models.swift` 引入 AppKit 和 SwiftUI；`Fetcher.swift` 内含 Mac 回环代理端口与兼容 User-Agent；`CredentialStore.swift` 没有启用 `kSecAttrSynchronizable`。因此是“共享核心 + 新建 iOS 产品”，不是简单加一个 iOS target 就能运行。

## 3. 用户任务与成功标准

| 用户任务 | 最短可理解路径 | 成功标准 |
| --- | --- | --- |
| 第一次查看额度 | 添加 → 校验 → 保存并查询 → 概览 | 不要求登录、通知权限或先购买 |
| 从 Mac 延续使用 | 两端主动开启同步 → 选择订阅 → 手机接收 | 明确等待/可查询状态，不自动上传未选中的 Mac 发现项 |
| 快速看一眼 | 小组件 → 对应订阅详情 | 同时看到来源/名称与更新时间，不混淆订阅 |
| 修复失败订阅 | 失败卡片 → 查看原因 → 编辑链接/重试 | 其他订阅继续可用，旧数据不被清零 |
| 不想用云 | 保持仅本机 → 手动导入 | 所有本地核心功能可用 |
| 移除或停用 | 管理 → 明确作用范围 → 确认 | 不取消服务商套餐，不删除其他客户端配置 |

产品验收采用任务完成率、误操作数和理解访谈；先用自愿 TestFlight 测试记录，不默认加入线上埋点 SDK。首轮目标建议：测试者不经指导能完成添加、找到更新时间、理解同步删除范围；量化结果待测试，不能提前写“95% 成功”。

## 5. Liquid Glass 视觉方向

### 5.1 设计主张：安静的内容，轻盈的操作

品牌温度来自粮袋、柔和琥珀点色与圆润数字；高级感来自信息秩序、材质节制和原生运动，不靠全屏金色、巨大 Logo、过多阴影或持续发光。

Apple 将 Liquid Glass 用作高于内容的导航和控制层。本方案采纳这种层次：导航、Tab、工具栏是玻璃；正文卡片是稳定、可读的内容表面。不是每张卡片都加折射与模糊。[Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)

### 5.2 四层材质

| 层级 | 本项目方案 | 禁止事项 |
| --- | --- | --- |
| 页面底色 | 系统分组背景；浅色暖白灰、深色石墨灰 | 大面积彩色渐变、噪点贴图、循环漂浮光斑 |
| 内容表面 | 系统次级背景、连续圆角、细微层次 | 流量文字背后放高对比插画或第二层玻璃 |
| 导航操作 | 原生 Tab/导航栏；少量自定义原生 glass 控件 | 手绘系统导航、玻璃套玻璃、多重按钮底板 |
| 临时表面 | 原生 sheet、菜单、确认框 | 与系统边缘返回冲突的全屏自定义手势 |

自定义玻璃仅在有真实交互的控件上使用 `glassEffect`；相邻自定义玻璃由 `GlassEffectContainer` 管理，检查静止时是否意外粘连。优先系统组件，而不是给每个 `VStack` 套玻璃。[SwiftUI 官方实现说明](https://developer.apple.com/documentation/SwiftUI/Applying-Liquid-Glass-to-custom-views)

### 5.3 设计变量（首轮原型基线，可经真机比较调整）

- 颜色：内容使用 `.primary` / `.secondary` 与系统背景语义色；琥珀作为按钮、选中、品牌插图点色。警告用橙，危险用红，不能依赖色相单独表达。
- 正常流量数字保持黑/白中性色；不把整个 App 染成金黄色。10%/20% 阈值见数据定义，不由设计稿随意改变。
- 主数值建议 40–48 pt、rounded semibold、等宽数字；正文采用系统 Body，辅助说明采用 Footnote，全部支持 Dynamic Type。大字体时重新排版，不把内容缩成小字。
- 普通 iPhone 页面水平留白建议 20 pt；卡片内部 20 pt；分组间距 24 pt；密集行间 8–12 pt。紧凑宽度适配到 16 pt，不锁死屏幕宽度。
- 主卡连续圆角建议 28 pt，次卡 20–24 pt；与内部控件形成协调关系。系统控件保持系统形状，不强行统一所有半径。
- 最小可点击区域 44 × 44 pt；视觉上很小的更多按钮仍有完整命中区域。[Apple UI 设计建议](https://developer.apple.com/design/tips/)
- 自定义运动建议 180–280 ms，仅说明层级变化；原生 sheet、导航和按钮反馈优先使用系统默认。不持续晃动粮袋，不用数字从 0 开始滚动制造假读数。

### 5.4 品牌资产继承

- 保留已选定的粮袋 App icon 与 C 方向灰阶粮袋装饰；不再重新设计独立爪印。
- 主卡粮袋正立、不倾斜，右下角局部出现，建议占卡宽约 25%–30%，不挤占数据与提示区域；大型文字/高对比模式下自动减弱或隐藏装饰。
- 粮袋是内容装饰，不是额外卡片。保持原图比例，不拉伸脚趾，不人为扩大卡片高度只为塞图。
- 浅色用浅灰装饰，深色用黑灰/白灰差；具体透明度以真机对比验证，不以截图滤镜模拟原生玻璃。
- MU Labs 标识只在欢迎/关于等适当位置小幅出现，不占用每页底部导航空间。
- App icon 按实际提交工具支持生成合格资产；检查浅色、深色和系统着色效果，不把带桌面阴影的截图直接当图标源。

## 6. 关键页面与 UX 细节

### 6.1 欢迎与首次使用

单页欢迎，不做强制三屏轮播。标题“看清每份订阅的剩余流量”，副文案解释需要支持流量信息的订阅链接。主按钮“添加订阅”，次入口“查看示例”；云同步是独立可选入口，不预勾选。

示例可让没有订阅的人体验完整导航、图表和小组件配置说明，但必须持续显示“示例数据”。示例与真实记录隔离，不同步、不发提醒、不产生真实流量查询。退出示例回到真实空状态。

首次不请求通知、相机、局域网等所有权限。用户点扫码时才请求相机；用户设置第一条提醒时才请求通知。拒绝后仍能手动输入并正常查看流量。

### 6.2 概览

自上而下：页面标题和添加 → 置顶订阅名称/来源 → 剩余主数字 → 明确标注“已用”的进度条 → 已用与总量 → 更新时间与状态 → 重置/到期摘要 → 其他订阅。

- 默认突出一个用户置顶订阅；没有置顶时沿用最近选择，不在刷新后自动换主卡。
- 不默认把不同服务商、不同周期的余额相加成“总流量”。概览可显示“3 份订阅，1 份需处理”，点击进入筛选列表。
- 同一主卡的无数据、成功、失败后旧数据保持稳定排版。辅助说明允许增高；不能为了完全固定高度截断重要原因。
- 下拉刷新只刷新当前可见/置顶的活跃订阅；“刷新全部”放入明确菜单，显示逐项结果，不因一个失败返回全屏错误。
- 点击主卡进入详情；点击日期摘要进入其解释/设置。长按可置顶/归档，但这些操作也出现在可见菜单中。
- 100% 剩余的示例对应已用 0%、进度条空；“100% 已用”和“100% 剩余”不能共用无标签的环形图。

### 6.3 订阅列表

每行显示名称、剩余量、最近更新时间及异常标签；不展示完整 URL。服务商名是用户名称或经校验的显示域名，不等于导入客户端名称。搜索只匹配名称/分组，不在结果中暴露令牌。

筛选：全部、需处理、已归档；排序：手动、剩余比例、到期日期。未知值排在已知值之后，排序规则可解释。手动排序、归档、置顶均有撤销与无障碍入口。

“归档”停止该设备主动查询并移出概览，可恢复；是否跨设备归档遵循同步的管理设置。“从此设备隐藏”是独立本机偏好，不改云端订阅。删除是单独危险操作，不通过全幅滑动无提示完成。

### 6.4 导入与编辑

流程：**选择输入方式 → 本机解析 → 显示名称/域名/来源预览 → 用户确认“保存并查询” → 安全保存 → 请求服务商 → 显示结果。**

- 支持主动粘贴、系统分享扩展、相机扫码；图片内二维码可通过系统照片选择器选择单张图片，不申请全相册读取。
- 只处理明确传入的内容，不在启动时读剪贴板，不注册/抢占其他客户端 URL Scheme。
- 输入区关闭自动大写、自动纠错和智能标点。URL 默认掩码；“显示链接”需要明确操作，离开页面恢复掩码。
- 首次请求前说明“将向该订阅地址查询流量”；校验界面不能先偷偷联网验证。
- 完整链接相同才提示重复。不同包装解析到同一地址可合并；同域名不同令牌不能当成同一账户。
- 不重排签名查询参数、不擅自解码/重编码 URL、不把 fragment 名称误存为令牌。
- 域名较长或疑似同形字符时显示可核对的实际主机；不把未经验证的外层品牌名当成安全背书。
- 批量导入逐项确认并保留部分成功；无流量数据仍可保存为“服务商未提供流量信息”，不把“不支持读数”伪装为“没有订阅”。
- 编辑链接创建新的凭据修订并再次查询；旧读数标记属于旧链接，不延续为新链接的有效余额。
- 扫码、分享扩展和导入页使用同一验证核心，恶意脚本/YAML 标签不能被执行。

### 6.5 订阅详情与历史

主区域延续概览语义；下面依次是上传/下载、到期与重置、最近观测曲线、订阅设置和来源说明。未知上传/下载各写“未提供”，不能平分 SIP008 合计用量。

历史首发定位为“观测记录”：7 天/30 天的已用或剩余采样点，显示缺口，不插值成精确日账单。只有两个点确属同一订阅、同一周期、同一额度口径且计数未回退时，才能显示“这两次读取之间增加了 X”。

计数回退、总量变化、链接更换或无法确认重置时断开曲线，标记“读数发生变化”；不自动宣称服务商已经重置。暂不提供“预计耗尽日”“本月准确用量”或虚假的日柱状图。

本机历史默认保留 90 天，用户可关闭记录、立即清空或导出不含 URL 的 CSV。云同步默认不含观测历史；两台设备的历史差异因此合理，页面应说明“此设备记录”。

### 6.6 重置与提醒

重置页面必须并列解释：服务商明确日期、客户端报告的倒计时推算、用户手动日期。手动设置优先显示，但保留原来源供查看；清除手动值后恢复原来源，无来源则回到未知。

首发手动重置仅设置下一次日期，不自动滚到下个月，也不清零真实额度。到期显示“已到设置日期，等待确认”。月底、闰年和时区不能依靠加固定秒数处理。

提醒设置使用独立表单，先解释依据再申请系统权限：到期可选提前 7/3/1 天；手动重置可选前一天/当天；低流量默认建议开启 10% 阈值，20% 为可选预提醒。阈值是对剩余比例，不是已用比例。

低流量提醒只在成功读取有效数据后判断，每个订阅/阈值/周期去重，设冷却；无可靠周期时以重新高于阈值并再次跌破作为重新触发条件，避免每次刷新骚扰。日期提醒可预先排程；未知未来额度不能预先制造低流量通知。

通知默认采用隐私内容“有一份订阅需要查看”，用户可选择显示名称与读数。通知点击进入对应页面；已删记录跳到列表并说明，不能打开错误订阅。多台设备各自启用提醒，首发不承诺跨设备绝对去重。

### 6.7 设置、隐私与诊断

外观：跟随系统/浅色/深色；单位：GiB/GB；语言：跟随系统并提供系统 App 语言入口；刷新：允许蜂窝、后台机会刷新说明；另含 iCloud、隐私、帮助。

诊断只导出错误类别、App/系统版本、尝试时间及脱敏状态。URL、令牌、服务商返回正文、设备名、Apple 账号不能默认入日志。导出前预览内容；由用户经系统分享发送，不自动上传后台。

主内容是工具本身，不设置每天弹出的评分、促销或“升级会员”横幅。

## 7. 数据语义契约

以下规则进入共享核心的单元测试；不能只写在帮助文档。

| 数据 | 定义与显示 |
| --- | --- |
| 原始单位 | 内部统一整数 bytes；计算做溢出与非负校验 |
| 显示单位 | 建议默认 GiB（2^30 bytes），可切换 GB（10^9 bytes）；界面正确标单位 |
| 现有差异 | 当前 `Fmt.swift` 用 1024 进制却标 GB；跨端开发需明确迁移，不静默混算，先保留原始 bytes 再统一显示 |
| 已用 | 完整有效的 upload + download，或明确的 SIP008 合计；缺一个拆分字段不自动按 0 补齐 |
| 剩余 | 已知有效 total 与 used 时 max(total − used, 0)；used 超额额外显示超出部分 |
| 百分比 | total > 0 且 used 已知才计算；进度条夹在 0…1，文字可表达实际超额；total=0 不当作无限或已耗尽 |
| 提醒颜色 | 保留现有边界：剩余 <10% 红，10%≤剩余<20% 橙，≥20% 正常；恰好 10% 不是红 |
| 套餐到期 | 服务商到期字段，缺失则未知；与重置日无推导关系 |
| 重置 | `providerExact`、`clientEstimate`、`manual`、`unknown` 分开建模；0 天不能误显示 0 流量 |
| 新鲜度 | `observedAt` 为本设备成功读取时间；客户端旧缓存另存 `sourceUpdatedAt`，未知不填当前时间 |
| 跨端缓存 | 若以后同步，必须标“Mac 上次读取”等来源；首发不跨设备同步额度读数 |
| 额度范围 | 是服务商账户/套餐范围，可能包含其他设备用量；不是本 iPhone 的网络消耗 |
| 历史比较 | 只有同订阅、同周期/可比口径才比较；不可比则断段并解释 |

主界面建议超过 15 分钟标“上次读取”，超过 24 小时增加过旧提示；这是产品信息提示，不是网络必定每 15 分钟运行的承诺。失败保留最后有效值和旧时间。

日期保存：绝对到期用 UTC instant，展示用系统日历；手动日期保存年月日与用户选择的时区，计算下次通知遵循日历日。切换时区或系统时钟发生变化时重算提醒，不修改服务商原始日期。

## 8. 客户端兼容与网络策略

### 8.1 兼容矩阵

| 来源 | 首发导入承诺 | 不承诺 |
| --- | --- | --- |
| Quantumult / Quantumult X | 用户提供的原始 HTTPS 订阅 | 自动读取 App 内部套餐、所有私有 URL Scheme |
| Surge | HTTPS、受支持 `MANAGED-CONFIG` 首行及导入包装 | 运行配置、操作 VPN、获取服务商未返回的重置日 |
| Stash / Clash 系 | 当前已验证规则范围内的导入包装与 HTTPS | 扫描移动端客户端配置 |
| Shadowsocks | HTTPS 返回的受支持 SIP008 流量字段 | 将 `ss://` 单节点当成套餐余额接口 |
| Hiddify / Loon / sing-box | 当前明确支持的 HTTPS 包装提取 | 执行节点或全部配置格式覆盖 |
| Shadowrocket / 其他工具 | 符合通用规则的 HTTPS 地址可尝试 | 未核实的专用接入或官方合作背书 |

准确格式继续以 [现有兼容性记录](client-compatibility.md) 为起点；任何新格式先取得官方说明与脱敏样例再加入。兼容某种订阅格式，不等于所有服务商都返回可读额度。

### 8.2 iOS 查询契约

- 使用系统 URLSession 路由，可能经过用户已有的系统 VPN/代理；不宣称能绕过它们。删除 Mac 的回环端口探测与强制代理配置。
- HTTPS-only；不关闭 ATS/证书校验，不提供“忽略证书错误”开关。仅同主机同端口 HTTPS 重定向，保留现有最多 10 跳限制。
- GET 响应拿到有效流量头后取消剩余正文；SIP008 回退限 2 MiB 应用正文。不能宣称完全不会接收正文前缀或总内存仅 2 MiB。
- 候选 User-Agent 兼容策略做受控样例验证；默认清楚标识 ByteKibble，必要兼容模式只影响协议协商，不伪装登录授权。不能为了让请求成功泄露额外账号信息。
- 每订阅最多一个在途请求，全局前台并发建议 2；批量先查可见和置顶项。取消、删除、切换链接均取消旧任务，晚到结果按订阅 ID + 凭据修订拒收。
- 对超时/暂时网络故障做有限退避；401/403 显示访问被拒绝而非武断“套餐到期”；429 尊重 `Retry-After`，手动刷新也不能突破服务器禁限时间。
- 单请求总超时建议 15 秒，自动一次失败后排入后续机会，不在后台无限循环；低电量/低数据模式减少非必要请求。
- 默认不探测局域网或任意端口。对回环、link-local、私有地址的输入/解析策略设专项测试；不以不完整的域名正则冒充 DNS rebinding 防护，不为了它破坏 TLS/SNI。
- 服务商正文和远端图标不持久化、不执行、不用于未经核实的外链。没有业务需要就不下载 favicon。

## 9. iCloud 同步：首发核心，但必须先打通

### 9.1 用户可理解的范围

同步默认关闭；两端都必须主动启用。在 Mac 展示可选订阅列表，用户选择后才上传。移动端默认不开启全量自动发现同步。

| 内容 | 默认策略 |
| --- | --- |
| 已选择的订阅 URL / 令牌 | iCloud 钥匙串，端到端加密同步 |
| 名称、分组、置顶顺序、手动重置日期 | 用户私有 CloudKit 元数据；敏感字段使用加密字段，不能笼统承诺整个数据库端到端加密 |
| 最近读数与观测历史 | 只留本机，各设备自己刷新 |
| 提醒开关、隐私显示、选中项 | 本机偏好，避免所有设备同时自动打开提醒 |
| 日志、原始响应、其他 App 配置 | 不同步 |

Apple 提供可同步钥匙串，但访问组、保护等级与同步属性须正确配置；可同步项目不能使用 `ThisDeviceOnly` 保护等级。[钥匙串同步 API](https://developer.apple.com/documentation/security/ksecattrsynchronizable) · [钥匙串同步安全](https://support.apple.com/guide/security/secure-keychain-syncing-sec0a319b35f/web)

### 9.2 推荐架构与前置验证

采用 **CloudKit 私有数据库管理订阅记录 + iCloud 钥匙串管理秘密**，不是用 UserDefaults 存完整 URL 后直接同步。元数据使用 CKSyncEngine 的变更/账号事件；不依赖 SwiftData 自动同步来掩盖凭据跨系统的状态差异。[CKSyncEngine 官方说明](https://developer.apple.com/videos/play/wwdc2023/10188/)

Mac 兼容约束：CKSyncEngine 需要 macOS 14+。建议保留现有 macOS 13 的本机功能，在 14+ 才开放新同步功能并做 availability 隔离；不能为了共享代码悄悄提高整个 Mac App 的最低系统版本。若必须让 macOS 13 也同步，需要另估较低层 CloudKit 适配，不属于现成复用。[Apple 同步示例的系统要求](https://github.com/apple/sample-cloudkit-sync-engine)

CloudKit 加密字段不能直接用于查询/排序，因此按 zone 变更拉取元数据，在本机排序；不把 URL 或其可猜测摘要做 recordName。[Apple 关于加密字段的说明](https://developer.apple.com/videos/play/wwdc2025/246/)

先做技术验证，不先注册假定可用的永久标识：

1. 用同一开发团队配置专属 App ID、私有 iCloud container 与最小钥匙串访问组；最终 ID 在 Developer Portal 核验后锁定。
2. 用正确签名的 iPhone 包与 Developer ID Mac 包做双向新增、修改、删除测试。Mac 的受限 entitlement 需要相应 provisioning profile，不是已有 Developer ID 签名就自动具备权限。[Mac 分发签名](https://developer.apple.com/documentation/xcode/creating-distribution-signed-code-for-the-mac/)
3. 验证共同 access group；App Group 文件容器共享不等于钥匙串共享。[钥匙串访问组](https://developer.apple.com/documentation/security/sharing-access-to-keychain-items-among-a-collection-of-apps)
4. 只用独立模拟凭据；测试系统钥匙串同步关闭、设备锁定、Mac 旧存储迁移、同账号与不同账号。不能擅自切换用户主设备的 Apple 账号。
5. 发布型签名通过后再集成 UI。若账户/profile 不支持，报告确切依赖；这会阻塞“带完整 iCloud 的首发”，不能把本地模拟结果当成功，也不静默改成 MU Labs 服务器存令牌。

### 9.3 记录、修订与一致性

- 本地 `SubscriptionRecord` 使用随机 UUID；不再用原始 URL 作为跨组件 ID。`credentialRevision`、`schemaVersion`、记录变更版本独立保存。
- URL 是凭据。新建/改链接先写入并读回钥匙串，再提交指向该修订的元数据；另一设备元数据先到但凭据未到时进入 `awaitingCredential`，不得用空链接或旧令牌查询。
- CloudKit 与钥匙串没有跨系统原子事务。需要持久化 outbox、可重入步骤、重试和失败恢复；保存成功不能等同于所有设备收到。
- 修改名称与手动日期可按字段合并；同一字段并发修改使用服务端版本/基线检测，保留冲突副本供选择。不得只用设备墙上时钟“最后写入获胜”。
- CloudKit 空间不足、配额/请求限流、服务暂时不可用分别处理；尊重服务器建议的重试时间。生产 schema 先部署并验证，再接入 TestFlight；开发容器成功不代表用户环境可用。
- 并发改链接时不能自动交叉拼接名称与另一份令牌；显示两份脱敏修订让用户选，旧记录保持可恢复。
- 重复订阅到达后在本机比较完整有效地址，提示合并；不上传明文 URL hash 作为全局去重索引，不自动删除用户已有记录。
- 同步内容有严格 schema、大小与数量上限；未知字段向前兼容，未知 major 版本只读提示升级，不能空解析后覆盖云端。

### 9.4 同步状态机与文案

| 状态 | 对用户的含义 | 操作 |
| --- | --- | --- |
| 仅本机 | 未开启，不发送同步内容 | 开启同步 |
| 正在检查 | 正在核对可用的云端记录 | 可继续看本机数据 |
| 待发送 | 本机已保存，云端尚未确认 | 保留队列；可重试 |
| 等待订阅凭据 | 已取得记录信息，秘密尚未可用 | 稍后再试；允许手动补入 |
| 本机已更新 | 本设备已应用已收到的记录 | 显示最近检查时间 |
| 需要处理冲突 | 两端修改不一致 | 选择保留版本 |
| 同步受限/失败 | 无法完成这一步 | 按可确认原因解释，保留本机可用内容 |
| 账号发生变化 | 旧账号内容不能直接并入新账号 | 暂停，提示处理本机副本 |

不显示没有依据的百分比进度、预计几秒到达或“所有设备已同步”。CloudKit 可用不等于 iCloud 钥匙串已启用；钥匙串本机写入成功也不证明远端已经收到。

### 9.5 关闭、删除、离线与账号切换

- “在此设备停用同步”：停止应用自己的云操作，读回并保留可用本机副本，不调用同步钥匙串删除。系统已经接管的钥匙串同步不受一个应用开关完全控制，说明中要讲清。
- “从此设备隐藏”：仅本机隐藏标记，不向其他设备删除。
- “从所有同步设备删除”：明确列出对象与影响，先写入带修订的删除标记，再异步移除对应秘密；删除标记失败时不得先删凭据导致其他设备出现空记录。
- “删除云端同步数据”是单独高风险流程，不能与关闭开关捆绑；本机可选保留副本，说明其他设备需联网处理且不能保证即时擦除其离线副本或系统备份。
- 删除标记保留策略建议 90 天；超过保留窗口的旧客户端先全量对账，不重放旧新增队列。删除与离线编辑冲突时不能把已删记录自动复活；恢复必须是显式新修订。
- 账号登出/切换：停队列、清理旧账号同步游标、隔离旧缓存，不自动把旧账号内容上传给新账号；用户明确选择后才把所选本机记录作为新导入。首版不能可靠确认身份边界时保持暂停。
- 不提供“卸载即彻底清除所有钥匙串/云端数据”的错误保证；在 App 内提供明确删除入口与说明。

这些状态需要两台真机/一台 Mac 联测，不以 mock、模拟器或单设备钥匙串检查代替。

## 10. 小组件、后台与系统能力

### 10.1 小组件规格

| 类型 | 内容 | 点击 |
| --- | --- | --- |
| 桌面小号 | 单订阅、剩余、剩余比例、更新时间 | 该订阅详情 |
| 桌面中号 | 单订阅完整摘要，或最多三份简表 | 点到对应订阅 |
| 桌面大号 | 多订阅概览与日期摘要 | 对应条目，不做复杂滚动 |
| 锁屏矩形/行内 | 选择显示剩余或到期摘要 | 进入 App；遵循隐私选项 |

WidgetKit 控制外部容器、系统着色和刷新预算；不要把 App 内的玻璃层原样套到小组件中。支持系统着色/深色，警告除了颜色还要有文字或符号。[小组件刷新机制](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date)

首发选择安全、可解释的缓存模式：Widget extension 只读 App Group 中的**脱敏展示快照**，没有订阅钥匙串访问权限，也不直接向服务商请求。App 前台刷新或系统给予后台机会后更新快照并请求时间线刷新。

因此小组件可以及时重算已知日期的相对展示，但**不能独立产生新的额度读数**。入口命名“打开并刷新”，不是假装在小组件中完成联网的按钮。无记录、已删除、未解锁、久未更新都有独立样式；敏感模式隐藏名称和具体数字。

### 10.2 后台策略

- 前台进入：先展示缓存，再按冷却规则刷新当前订阅；查询不阻塞页面导航。
- 用户刷新：单订阅任务合并，网络结果到达后原子替换样本，避免数字/百分比来自不同次响应。
- 后台：申请 BGAppRefreshTask 作为机会式更新；过期回调立即取消并保存必要状态。不借音频、定位、蓝牙或 VPN 权限保活。
- iCloud 变更通知用于同步变更，不拿它制造无限额度轮询。不给一个用户发送包含其服务商令牌的自建推送。
- 系统可能不给后台时间，强制退出后也不保证继续工作；帮助文案明确需要打开 App 刷新。此限制决定了产品不能承诺“实时监测”。[Apple 后台策略](https://developer.apple.com/documentation/BackgroundTasks/choosing-background-strategies-for-your-app)

### 10.3 分享扩展与快捷指令

分享扩展只处理用户本次提供的内容。校验后把待导入凭据写入 App 与扩展专用的本地钥匙串访问组，App Group 只传随机待办 ID；不将原始 URL 暂存在普通 JSON 文件。用户在扩展明确确认，主 App 完成查询；临时项目有超时清理与重复提交保护。

App Intents 首发可提供“打开订阅”“打开并刷新”；只传随机 ID，不在 deep link query 或 Spotlight 中塞令牌。若未来输出具体读数到快捷指令，增加主动授权和锁屏认证要求，不默认让语音播报敏感数据。

## 11. 附近设备传输与备份（P1 的完整方案）

### 11.1 附近传输，不命名为持续蓝牙同步

用途：用户不使用 iCloud 时，从 Mac 向 iPhone 手动发送所选订阅。仅主动进入发送/接收页时发现设备，传输完成即结束，不在后台持续扫描。

技术优先研究 Network framework + Bonjour/peer-to-peer Wi-Fi，使用系统 TLS 和经过身份绑定的配对。Apple 已提供从 Multipeer Connectivity 迁移至 Network framework 的专门指导，因此不把前次讨论提到的 MultipeerConnectivity 直接锁定为新工程方案，也不承诺纯蓝牙传输。[TN3213](https://developer.apple.com/documentation/technotes/tn3213-moving-from-multipeer-connectivity-to-network-framework)

交互：选订阅 → 发现接收方 → 双端确认 → 加密发送 → 接收预览 → 明确保存 → 双端结果。设备名不等于可信身份；优先用二维码绑定临时公钥/会话信息，短码核对方案必须与认证协议绑定并通过中间人测试。二维码本身不含原始订阅令牌。

配对有超时、失败次数限制与一次性 nonce；不广播订阅名或链接。拒绝、退后台、断网、重复包、超大包、协议版本不一致均有恢复路径。接收只写 ByteKibble，不打开外部 VPN 客户端。

如果本地网络不可用，提示同一网络条件与系统权限，不退回明文或偷偷走云。蓝牙权限仅在真正采用相应 API 时申请，不能为了“附近传输”一概要求所有权限。

### 11.2 数据可携带性

P0 可导出不含凭据的历史 CSV；完整订阅备份属于 P1：用户输入口令、使用经过审查的标准 KDF 与认证加密生成版本化文件，导出前显示包含哪些秘密。不得自己设计加密算法，不可把密钥写在同一文件明文部分。

恢复先验证完整性和口令、预览重复与冲突，再事务性写入；取消/错误不能破坏现有订阅。明确口令无法由 MU Labs 找回，不将备份口令发送服务器。不把原始订阅 QR 或未加密文本作为默认分享方式。

## 12. 安全、权限与隐私契约

| 用户动作/通道 | 可以发生 | 绝不能默认发生 |
| --- | --- | --- |
| 打开 App | 读取本机记录；按已启用策略刷新 | 扫描其他 App、读剪贴板、上传历史 |
| 首次导入 | 本机解析；确认后保存并联系指定端点 | 自动跑配置、脚本或上传转换服务 |
| 刷新 | 向服务商发送该请求需要的 URL/令牌 | 发送到 MU Labs、诊断平台或其他订阅服务商 |
| 开启同步 | 按选择通过 Apple 服务同步 | 上传所有 Mac 自动发现项目 |
| 导出诊断 | 用户预览后主动分享脱敏材料 | 默认包含原始 URL、Cookie、响应正文 |
| 删除 | 按明确范围删除 ByteKibble 的数据 | 删除客户端配置、取消供应商套餐、抹除系统备份 |

储存方案：本地凭据默认仅解锁时可读；本地数据文件采用适当 Data Protection。为了后台读数而采用首次解锁后可读的钥匙串等级属于明确安全权衡，需要单独评审与文案，不暗中降低保护。设备未解锁时无法读凭据即保留旧快照，不绕过保护。

本机凭据优先采用 `WhenUnlockedThisDeviceOnly`；用户主动开启同步后创建可同步的 `WhenUnlocked` 项，并保留迁移恢复步骤，不能把两种属性组合成无效项目。`CredentialVault` 返回类型必须区分不存在、暂不可读、拒绝与其他失败；当前 `read -> String?` 不足以表达这些状态，移植时须改造，不把读失败当作已删除。

“默认本机”还应解释系统备份边界：ByteKibble 不主动把未选择的内容写入同步服务；本机缓存、历史和临时导入文件按最小化原则设置备份排除，秘密不进入普通备份文件。用户自行产生的导出文件及系统已有备份另有生命周期，不能承诺 App 能撤回所有副本。

后台刷新开关不能自动修改秘密保护等级；安全存储与业务重试状态分别管理。Face ID 可用于查看/复制原始链接、导出等敏感操作，但不是 iCloud 凭据加密的替代品；支持系统设备密码回退和失败/取消状态。

云端元数据与钥匙串令牌采用不同保护机制。宣传只能准确说“订阅凭据通过 iCloud 钥匙串端到端加密同步”，不能把所有日志、CloudKit 字段、备份和网络都概括成同一保证。

权限最小化：相机用于扫码；Face ID 用于敏感操作确认；通知用于用户设定提醒；照片使用 picker；附近传输加入后才声明并申请局域网。无需定位、通讯录、麦克风、跟踪权限和 VPN entitlement。

App 隐私声明要依据最终数据流与实际 SDK 填写，不能因为没有自建服务器就直接选择“未收集数据”。梳理服务商请求、Apple 同步、可选支持材料及未来 StoreKit；对隐私标签逐项留证。[App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/)

候选隐私说明（实现验收后才能公开）：

> 订阅默认保存在本机。刷新流量会联系你添加的订阅服务商。开启 iCloud 同步后，所选订阅和管理设置会通过 Apple 服务在你的设备间同步；订阅凭据使用 iCloud 钥匙串保护，不经过 MU Labs 服务器。小组件显示最近一次读取结果，刷新时间由系统和网络条件共同决定。

## 13. 状态设计总表

| 状态 | 页面表现 | 恢复与禁止行为 |
| --- | --- | --- |
| 空状态 | 简短说明 + 添加/示例 | 不先显示 0 GB |
| 首次加载 | 保留名称，数字骨架或“正在查询” | 可离开，不能无限转圈 |
| 有效数据 | 额度 + 来源 + 时间 | 原子更新整组指标 |
| 部分字段缺失 | 已知字段正常，其他“未提供” | 不隐藏整张卡，不猜数 |
| 查询失败且有缓存 | 旧值 + “未能更新” + 原更新时间 | 保留数据，提供重试/编辑 |
| 查询失败无缓存 | 清晰原因与操作 | 不当成额度耗尽 |
| 低额度/耗尽 | 红/橙 + 明确状态词 | 不把请求失败写成耗尽 |
| 套餐到期 | 日期过期标签 | 仍保留额度独立意义，不推断链接无效 |
| 手动重置日已到 | “已到设置日期” | 不清零、不滚动下一周期 |
| 凭据不可读 | “暂时无法读取订阅链接” | 不删记录、不重复触发系统授权 |
| 同步部分成功 | 本机可用项继续显示 | 不把云端失败扩大为全局不可用 |
| 云端记录先到 | “等待订阅链接同步” | 不使用旧凭据查新记录 |
| 权限拒绝 | 显示功能受限及手动替代 | 不阻止其他功能 |
| 未知 schema | 只读/提示更新 | 不清空后上传 |
| App 回到前台 | 恢复当前订阅/滚动位置 | 不重播欢迎、不跳回列表顶部 |

关键文案遵循“说明事实、影响和可执行下一步”，不写“绝对安全”“已同步到所有设备”“订阅丢失”等无证据承诺。示例：“未能更新，仍显示上次读取的数据。”；“停止此设备的同步？本机副本会保留，其他设备不受此操作影响。”后者须与系统钥匙串接管的边界一起说明。

## 14. 无障碍、本地化与高端体验验收

- 首发界面语言：简体中文、繁体中文、英语、日语、韩语。UI 使用 String Catalog、完整句子、变量与复数规则；不按中文长度硬编码胶囊宽度。
- VoiceOver 按“订阅名 → 剩余 → 已用/总量 → 更新时间 → 状态 → 操作”顺序；装饰粮袋不重复朗读。图表提供等价摘要和可遍历的数据点。
- Dynamic Type 最大无障碍字号下，双列统计变单列，完整日期可换行；不把重要信息统一省略成“2027 年 3 月 1…”。[Dynamic Type 指导](https://developer.apple.com/videos/play/wwdc2024/10074/)
- Reduce Motion 关闭自定义位移/缩放转场与数值滚动；保留简单状态切换。Reduce Transparency / 增强对比时确保有足够不透明底色，不强行覆盖用户的系统玻璃设置。
- 手势均有按钮/菜单替代；支持返回手势、键盘焦点、Switch Control 基本操作。拖动排序不成为唯一排序入口。
- 深浅色、高对比、系统着色小组件都检查红/橙状态；建议文字对比至少 4.5:1、较大文字 3:1，作为项目验收阈值，不声称玻璃材质天然通过。
- 删除不使用轻微 haptic 代替确认；保存成功只给一次反馈，刷新失败不持续振动。
- 所有外部文字视为不可信数据：超长名称、换行、RTL、Emoji、零宽字符、格式占位符不破坏布局或执行逻辑。

视觉验收必须用运行中的原生候选包：同一场景的浅/深色、小屏/大屏、普通/大字体对照。生成图只可作为设计参考，不能当成 App Store 实机截图或交互验收。

## 15. 工程架构与迁移路径

| 模块 | 职责 | 依赖限制 |
| --- | --- | --- |
| ByteKibbleCore | 导入规则、Quota、日期/比例、错误类型 | Foundation 为主；无 AppKit、SwiftUI、Sparkle |
| SubscriptionRepository | 元数据、本机状态、事务、历史与索引 | 不把原始 URL 暴露给 UI 日志 |
| CredentialVault | 本机/同步钥匙串、访问状态、凭据修订 | 秘密只在需要请求/显示时短暂读取 |
| QuotaService | HTTPS 请求、解析、限流、取消 | 平台注入 transport；iOS 无端口扫描 |
| SyncCoordinator | CloudKit、outbox、冲突、删除标记、账号隔离 | 不执行额度查询，不保存明文秘密 |
| RefreshCoordinator | 前后台预算、优先级、合并与取消 | 全局控制并发与服务器退避 |
| NotificationPlanner | 日期任务、阈值去重、权限与隐私 | 不对未知数据生成提醒 |
| WidgetSnapshotStore | 脱敏快照、时间线、随机路由 ID | 无钥匙串或 provider 请求权限 |
| iOS / iPadOS App | SwiftUI 页面、导航、设置、无障碍 | UI 状态消费领域结果，不自行算额度 |
| Share Extension | 用户选择内容的安全接收 | 临时秘密入受限钥匙串，非普通共享文件 |
| macOS Adapter | 现有自动发现、菜单栏、Sparkle、同步设置 | Mac 专用逻辑不进入 iOS target |

数据建议：订阅元数据与观测用本地持久存储，优先选可维护的 Core Data 本地 store；CloudKit 通过独立同步协调器接入，不给整个 store 无差别自动同步。若技术验证证明另一持久层更简单，应在正式开工前改一次架构记录，不在两种数据库间长期双写。

并发：网络/解析/同步在独立 actor 或任务中，UI 更新回 MainActor；成功/取消/失败只完成 continuation 一次。每次查询携带订阅 UUID 与凭据修订，以抵御删除后旧结果复活。

迁移按步骤进行：

1. 抽出纯解析/格式化核心，保留 Mac 外观与已有测试；拆开 `WarningLevel` 的业务阈值和平台颜色。
2. 引入显式 `unknown/partial` 模型，不让缺字段隐式返回零；做 Mac 与 iOS 共享回归。
3. 新增 UUID 元数据模型，建立旧 URL/hash 标识到新记录的本机迁移表；成功读回再提交，不清理其他客户端配置。
4. 新建 Xcode iOS App、Widget、Share extension；分别校验签名与 entitlements，不复制 Mac 的 Sparkle target。
5. 先完成本机垂直流程，再启用经过验证的同步模块；Mac 的同步迁移必须有旧安装包升级测试与可恢复失败路径。
6. 同步 schema 和 App 版本分离，旧客户端遇到新 schema 安全只读；取消同步不会写回旧格式覆盖新数据。

下表是工程目标，须在最低支持真机 Release 构建测量，不是已经达成的指标：

| 项目 | 初始目标 | 证据 |

## 17. App Store 上架方案

### 17.1 真实定位，而不是规避审核

建议分类 Utilities，商店名候选“ByteKibble — 字节猫粮”，副标题候选“订阅流量与到期提醒”；长度、重名与可用性提交前实际验证。

审核说明应准确写：用户导入已有 HTTPS 订阅，App 仅读取支持的流量信息；不提供 VPN 服务、不建立隧道、不售卖节点、不修改网络配置。是否适用 VPN 相关要求由真实功能和审核判断决定，不能靠名称保证豁免。若未来加入 VPN 功能，需重新评估组织账号、API 与地区许可；不得隐藏功能或对审核环境特殊伪装。[App Review Guidelines 5.4](https://developer.apple.com/app-store/review/guidelines/#vpn-apps)

完整性上，原生管理、同步、小组件、历史和提醒构成真实用途，但堆功能不保证满足审核。提供所有人可进入、标注清楚的演示；若审核需要网络路径，另给受控测试端点与无权限的模拟数据，绝不提供真实付费订阅令牌。[审核提交准备](https://developer.apple.com/app-store/review/guidelines/#before-you-submit)

### 17.2 账号、名称、地区

- iOS 使用 Apple Distribution / App Store provisioning 与 TestFlight，不以 Mac Developer ID 或 notarization 作为 iOS 上架证明。Mac 公证是另一个分发流程。
- App 内品牌继续使用 MU Labs。App Store 开发者/销售方名称受注册主体约束，不能直接把个人法定姓名通过 UI 文案改成 MU Labs；若要求商店也呈现品牌主体，先核验组织账号与合法商号条件。[开发者名称规则](https://developer.apple.com/help/app-store-connect/create-an-app-record/set-your-developer-name)
- App ID、iCloud container、access groups 只在实际团队核验后创建；钥匙串跨团队不能假设互通。账号转移风险要在创建长期同步标识前评估。
- 首发销售地区是待确认的发行选择，不能默认全球开放。中国大陆需核验 App 信息中的备案及其他适用材料；未满足则不声明已经可上架该区。[App Store Connect App 信息](https://developer.apple.com/cn/help/app-store-connect/reference/app-information/app-information)
- 欧盟发行需完成适用的 trader status 与联系方式验证；不能用品牌偏好掩盖法定披露。[DSA 信息要求](https://developer.apple.com/help/app-store-connect/manage-compliance-information/manage-european-union-digital-services-act-trader-requirements)

### 17.3 隐私与加密材料

- 提供公开可访问的隐私政策、支持页面及联系渠道；App 内与商店元数据一致。云同步、服务商请求、提醒、小组件的实际行为逐项声明。
- App 与扩展检查 `PrivacyInfo.xcprivacy` 和 Required Reason APIs（例如实际使用的偏好/文件 API）；依据实际用途填理由，不抄一组全量代码。检查第三方依赖所需的清单/签名。[Privacy manifest files](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files)
- TLS、钥匙串、同步以及未来备份加密都纳入 export compliance 问卷；可能适用豁免不等于无需判断。`ITSAppUsesNonExemptEncryption` 依据实际功能与材料设置，不习惯性填 false。[加密出口合规](https://developer.apple.com/help/app-store-connect/manage-app-information/overview-of-export-compliance/)
- 年龄分级按当前问卷真实填写，不提前保证某个等级。最终检查当时的正式 SDK、权限说明与审核规则。

### 17.4 商业化建议（不擅自决定售价）

建议首个 TestFlight 与初次功能验收不加入付费门槛；商业版本可选免费或一次性非消耗型 Pro。当前没有 iOS 产品价格决定，不沿用其他项目或旧讨论里的数字。

若收费，核心安全、查看已有数据、关闭同步和删除/导出本人数据不得被支付墙阻挡。Pro 可围绕高级布局/批量管理/长期历史等持续可用功能，但最终权益表在实现前单独锁定；不为了年费人为限制“是否加密”。

不单独售卖 iCloud 空间或收取“访问 iCloud 服务”的费用；云同步不作为本方案的单独收费项目。[Apple Developer Program 协议的 iCloud 条款](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/)

数字功能采用标准 StoreKit 内购路径；首发不做站外支付导流、兑换码授权系统或地区特殊支付分支。恢复购买、取消、待批准、验证失败、退款/撤销分别处理，价格与币种来自 StoreKit，不写死。[App Review Guidelines 3.1.1](https://developer.apple.com/app-store/review/guidelines/#in-app-purchase) · [恢复购买](https://developer.apple.com/documentation/storekit/appstore/sync%28%29)

服务商套餐的 Premium 与 ByteKibble Pro 分开命名、分开模型；iCloud 登录状态也不等于 App 内购权益。未确认前不承诺 GitHub Mac 用户与 iOS 付费通用。

### 17.5 提审材料包

| 材料 | 完成标准 |

### 18.2 测试层次

1. 共享逻辑：单元/属性测试与恶意输入 fuzz；同一 fixtures 在 Mac/iOS 核心跑。
2. 服务集成：可控 HTTPS fixtures 验证证书、头优先、正文限制与取消；不使用真实令牌入测试仓库。
3. UI：XCUITest 验证关键路径与恢复；截图比较验证材质、字体、边缘与状态。
4. 设备：iPhone + Mac 的同账号同步真测；第二测试账号隔离真测；iPad 窗口与小组件真测。
5. TestFlight：distribution 签名、生产 CloudKit schema 与接近真实使用的升级路径。不能继承开发容器的通过结论。

每次证据记录版本/commit、构建类型、设备/系统、场景、预期/实际、截图或日志、是否模拟数据。旧截图可以参考，不成为新候选的验收证据。

### 18.3 首发 Go / No-Go

以下任一项未通过，不宣称“全功能已完成、可发布”：

- 秘密进入普通日志/快照/CloudKit 明文字段，或未确认前自动外发。
- Mac↔iPhone 发布型签名同步未通过，跨账号混合，删除/冲突可能丢失数据。
- 无数据显示 0、超额/未知/过旧被画成正常，错误订阅收到了别人的结果。
- 关键操作崩溃、不可恢复卡死、VoiceOver 无法完成导入/删除。
- iCloud/相机/通知权限被拒绝后，本地主要功能不可用。
- 必填上架资料、地区资格、SDK、签名或演示验证条件缺失。

仅主观偏好争议、无关警告不是无限延期理由。发布门槛按上述可观察条件收口；“已实现、已本地验证、已真机验证、已 TestFlight、已上架”分别记录。
