<h1 align="center">ByteKibble</h1>
<p align="center"><a href="https://mustundead.com">Mustundead의 MU Labs</a> 제작</p>
<p align="center">구독 데이터 잔여량을 한눈에.</p>
<p align="center"><a href="README.md">简体中文</a> · <a href="README.zh-Hant.md">繁體中文</a> · <a href="README.en.md">English</a> · 한국어 · <a href="README.ja.md">日本語</a></p>

ByteKibble은 macOS 메뉴 막대에서 구독 데이터 사용량을 확인하는 네이티브 앱입니다. Clash 계열 클라이언트와 SNTP 사용자가 궁금해하는 **“이 구독으로 데이터를 얼마나 더 쓸 수 있을까?”**에 답합니다. 클라이언트나 제공업체 웹사이트를 매번 열지 않고 사용량, 만료일, 데이터 출처를 확인할 수 있습니다.

> **현재는 문서와 아이콘만 업데이트했습니다.** 이 페이지는 다듬고 있는 새 버전을 소개합니다. 해당 앱 코드, 첫 실행 환영 화면, ZIP/DMG 패키지는 이번 업데이트에 포함되지 않았습니다. 기존 코드와 `preview/`의 과거 스크린샷은 이 페이지의 새 디자인과 다릅니다. 다운로드는 [Releases](https://github.com/mustundead/ByteKibble/releases)에 실제로 게시된 버전을 기준으로 확인하세요.

## 주요 기능

- **메뉴 막대에서 잔여량 확인**: 숫자는 남은 데이터양, 원형 그래프는 남은 비율을 표시합니다. 클라이언트에 초기화 정보가 있으면 카운트다운도 표시합니다.
- **하나의 패널에 모은 상세 정보**: 요금제 이름, 남은 양/사용량/전체 한도, 업로드와 다운로드, 예상 초기화 날짜, 구독 만료일, 출처와 업데이트 시각을 확인합니다.
- **여러 구독 전환**: 읽을 수 있는 클라이언트 설정에서 구독을 찾거나 HTTPS 구독 링크를 직접 추가해 각각의 사용량을 확인합니다.
- **필요할 때만 경고**: 잔여량이 20% 미만이면 주황색, 7% 미만이면 빨간색으로 표시합니다. 부족하거나 소진된 상태는 글자로도 안내합니다.
- **macOS에 맞는 사용 경험**: SwiftUI, 라이트/다크 모드, 고정 폭 숫자, 동작 줄이기 지원, 켜짐/꺼짐이 명확한 로그인 시 자동 실행 표시.
- **5개 인터페이스 언어**: 중국어 간체, 중국어 번체, 영어, 한국어, 일본어.

ByteKibble은 **프록시 클라이언트, VPN, 속도 측정 도구 또는 앱별 네트워크 사용량 측정기가 아닙니다**. Clash/Mihomo 대신 트래픽을 라우팅하거나 제공업체의 데이터 한도를 변경하지 않습니다.

## 색상과 진행률 읽기

| 남은 데이터 비율 | 표시 | 의미 |
| --- | --- | --- |
| 20% 이상 | 화면 모드에 맞는 검정/흰색 기본 색상 | 정상 |
| 7% 이상, 20% 미만 | 주황색 | 잔여량 부족 |
| 7% 미만 | 빨간색 | 잔여량이 매우 적거나 소진됨 |

메뉴 막대의 원형 그래프는 **남은 비율**을, 상세 카드의 가로 막대는 “사용량” 백분율과 같은 **사용한 비율**을 나타냅니다. 경고색은 데이터 잔여량의 위험 수준만 뜻하며 요금제 등급, 연결 상태, 자동 실행 설정을 나타내지 않습니다. 초기화 날짜가 가까워지는 것 자체는 오류가 아닙니다.

## 데이터 출처

| 출처 | 자동으로 읽는 정보 | 참고 |
| --- | --- | --- |
| Clash Verge / Clash Verge Rev | 로컬 `profiles.yaml`의 구독 링크 | 사용량은 제공업체에 조회합니다 |
| ClashX / ClashX Meta / ClashX Pro | 클라이언트 환경설정의 구독 링크 | 읽을 수 있는 형식으로 저장되어 있어야 합니다 |
| SNTP | 구독 링크, 요금제와 사용량 캐시, 클라이언트가 보고한 초기화까지의 일수 | 캐시에 신뢰할 수 있는 원래 업데이트 시각이 없을 수 있습니다 |
| 직접 추가 | 붙여 넣은 HTTPS 구독 링크 | 제공업체가 해석 가능한 사용량 정보를 반환해야 합니다 |

최신 사용량은 구독 요청에 대한 `subscription-userinfo` 응답 헤더에서 가져옵니다. **Mihomo 코어를 사용한다고 자동으로 감지되는 것은 아닙니다**. 자동 감지는 위 표의 저장 형식을 지원합니다. 다른 클라이언트에서는 구독 링크를 직접 추가해 볼 수 있습니다.

ByteKibble이 모든 네트워크 트래픽을 직접 측정하는 것은 아닙니다. 수치는 제공업체나 클라이언트가 반환한 값에 따릅니다. 헤더 누락, 필수 필드 부족, 전체 한도가 0인 경우 또는 조회 실패를 “측정된 잔여량 0”으로 해석하면 안 됩니다. 이전 수치를 볼 때는 출처와 업데이트 시각도 확인하세요.

### 초기화 날짜와 새로 고침

- 초기화까지의 일수는 클라이언트가 보고한 값이며 일반 구독 헤더의 표준 필드가 아닙니다. 카운트다운과 **예상 날짜**는 이 일수로 계산하며, 제공업체가 확정한 초기화 시각이 아닙니다. 오래된 캐시는 정확도에 영향을 줄 수 있습니다.
- 정보가 없으면 날짜를 추측하지 않습니다. 구독 만료와 데이터 한도 초기화는 서로 다른 개념입니다.
- 앱 실행 중 주기적으로 갱신하며 직접 새로 고칠 수도 있습니다. 잠자기, 네트워크, 제공업체 응답 때문에 지연될 수 있습니다.
- 직접 연결과 일반적인 로컬 프록시 포트(`7899`, `7890`, `7897`)를 시도합니다. 프록시 클라이언트를 실행하거나 시스템 프록시 설정을 변경하지 않습니다.

## 시스템 요구 사항과 설치

**macOS 13 이상**이 필요합니다. 네이티브 Liquid Glass 스타일은 macOS 26 이상에서 사용하며 이전 시스템에서는 호환 스타일을 사용합니다. 프로세서 지원, 서명, 공증 여부는 각 패키지의 릴리스 설명을 확인하세요.

드래그로 설치하는 ZIP/DMG와 한 페이지 환영 화면은 준비 중입니다. **이번 문서 업데이트에는 새 설치 파일이 포함되지 않습니다.** 게시 후 이 저장소의 [Releases](https://github.com/mustundead/ByteKibble/releases)에서 받을 수 있습니다. ZIP은 압축을 풀고 앱을 “응용 프로그램”으로 옮기고, DMG는 열어서 앱을 “응용 프로그램” 바로가기로 드래그합니다. 이동한 앱을 “응용 프로그램”에서 실행하세요.

macOS가 실행을 차단하면 먼저 다운로드 출처, 서명, 릴리스 설명을 확인하세요. 파일을 신뢰할 수 있는 경우에만 [Apple의 안내](https://support.apple.com/guide/mac-help/mh40616/mac)에 따라 “시스템 설정 → 개인정보 보호 및 보안”에서 처리하세요. **서명과 공증은 다릅니다.** 설치를 위해 시스템 보안 기능을 끄지 마세요.

지원되는 클라이언트에 구독을 가져오거나 ByteKibble에 HTTPS 링크를 추가하면 됩니다. 앱은 메뉴 막대에서 동작합니다. 로그인 시 자동 실행은 선택 사항이며 잔여량 확인에 필수적이지 않습니다.

## 개인정보 보호와 범위

자동 감지는 로컬 클라이언트 설정을 읽습니다. 직접 추가한 링크는 ByteKibble의 로컬 환경설정에 저장됩니다. 추가, 삭제, 실행 취소는 앱 자체 목록만 바꾸며 **제공업체의 구독을 수정하거나 해지하지 않습니다**.

구독 URL에 액세스 토큰이 포함될 수 있으므로 비밀번호처럼 관리하세요. 조회는 해당 제공업체로 전송됩니다. 로컬 프록시를 사용하면 요청은 해당 프록시에 설정된 경로로 전달됩니다. ByteKibble에는 자체 트래픽 중계 서버가 없으며 구독 링크를 분석 플랫폼으로 보내지 않습니다.

공개 Issue나 스크린샷에서 구독 URL, 토큰, 계정 정보를 가려 주세요.

## 소스에서 빌드

Swift 도구 모음이 포함된 Xcode를 설치한 뒤 실행하세요.

```bash
git clone https://github.com/mustundead/ByteKibble.git
cd ByteKibble
swift build -c release
```

서드 파티 런타임 의존성은 없습니다. 빌드 성공이 서명, 공증 또는 설치 파일 검증 완료를 뜻하지는 않습니다. 문서를 앱 코드보다 먼저 업데이트했으므로 실제 빌드 동작은 체크아웃한 코드에 따릅니다.
